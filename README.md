# دَرْب AI (DARB AI)

🌐 **الموقع:** https://ahsasgaly11-ai.github.io/darb-ai/ — يُحدَّث آليًا كل يوم.

**نظام ذكاء اصطناعي للتنبؤ بمخاطر الطرق وتحسين الصيانة الوقائية في دول الخليج** — نموذج أولي يعمل على **كاميرات مرور حقيقية مفتوحة بدقة 1920×1080** في خمس مدن قريبة من بيئة الخليج: **فينكس وتوسان ويوما (أريزونا)** الصحراوية الحارة الجافة، و**سنغافورة** و**تامبا (فلوريدا، على خليج المكسيك)** الحارتين الرطبتين.

يلتقط النظام صور الطرق على فترات منتظمة، ويكتشف عيوب الرصف **بالذكاء الاصطناعي**، ويتتبّع كل عيب أسبوعًا بعد أسبوع. ويدير كل مشكلة عبر دورة حياتها:
- **قبل**: يتوقع التدهور قبل حدوثه.
- **أثناء**: ينبّه فور وقوع مشكلة، حتى المفاجئة منها.
- **بعد**: يرصد الإصلاح تلقائيًا ويراقب المقطع حتى لا يعود العيب.

## ما الذي يفعله النظام؟

| المرحلة | التفاصيل |
|---|---|
| **الالتقاط** | التقاط **يومي** لكل كاميرا بين 9 و12 صباحًا بالتوقيت المحلي لكل منطقة: دفعة من 5 إطارات يُحسب وسيطها فتختفي المركبات. الاشتباه بحدث مفاجئ يُعاد التقاطه بعد ساعة. لا التقاط ليلًا. كاميرات سنغافورة لها أرشيف، فيُبنى سجل 6 أشهر من صور حقيقية فور التشغيل. |
| **تنظيف الصورة** | وسيط زمني على عدة إطارات يُخفي المركبات، ومؤشر «حجب» يستبعد لحظات الازدحام ويجرّب لحظات أوضح، ومحاذاة ORB تعوّض اهتزاز الكاميرا. |
| **الذكاء الاصطناعي** | تجميع (Ensemble) نموذجَي YOLO مدرّبين على **RDD2022**، المجموعة الدولية لعيوب الطرق: تشقق طولي وعرضي وتمساحي وحفر وترقيعات. تُقطَّع منطقة الطريق إلى بلاطات بالدقة الكاملة لاكتشاف التشققات الصغيرة في الكاميرات البعيدة، ويُحسب **مؤشر حالة 0–100** بمنحنيات خصم على غرار ASTM D6433 (PCI). |
| **تتبّع العيوب** | كل عيب يُطابَق مع اللقطات السابقة بموقعه، فيُعرف أول ظهوره، ونموّه الأسبوعي، واختفاؤه أو ترقيعه. |
| **قبل** | نموذج مخاطر **قابل للتفسير** يجمع: الحالة الحالية، سرعة التدهور، الحرارة (Open-Meteo لكل منطقة)، المدى الحراري اليومي، المرور والشاحنات، عمر الطبقة. يتوقع موعد بلوغ عتبة الصيانة ويفتح **«مشكلة متوقعة»** إذا كان خلال 12 أسبوعًا. |
| **أثناء** | تحقق التوقع، أو حدث مفاجئ مؤكَّد في لقطتين متتاليتين (حفرة، هبوط، مخلّفات)، يفتح **«مشكلة نشطة»** مع تنبيه وتوصيات عملية. |
| **بعد** | رصد **تلقائي** لزوال المشكلة (إصلاح أو إزالة)، وقياس زمن المعالجة، ثم **مراقبة 8 أسابيع** وتنبيه إن عاد العيب. تسجيل الصيانة يدويًا يغلق المشكلة أيضًا. |
| **مؤشرات الأداء** | مدة سبق التنبؤ للحدث، ودقة التنبؤ، وزمن المعالجة، ونسبة العودة بعد الإصلاح. |

### كم صورة، وكل كم؟
| الهدف | الإعداد | السبب |
|---|---|---|
| إزالة المركبات | 5 إطارات في كل التقاط (فيديو: كل 4 ثوانٍ؛ صور متجددة: كل صورة جديدة خلال دقائق؛ أرشيف: كل دقيقة) | الوسيط الزمني يزيل المتحرك؛ أقل من 3 لا يكفي وأكثر من 9 لا يضيف |
| ثبات الإضاءة | مرة يوميًا بين 9 و12 صباحًا محليًا (المستهدف 10:00) | ضوء جيد قبل تموّج الهواء من حرارة الأسفلت ظهرًا |
| المفاجآت | يوميًا + تأكيد بعد ساعة | التنبيه لا يُطلق إلا إذا بقي الحدث في التقاطين |
| الاتجاه والتنبؤ | نقطة أسبوعية = وسيط أيام الأسبوع، والأيام السبعة الأخيرة نقاط يومية | يوم شاذ لا يؤثر، والتغيّر الذي يبقى يومين يظهر فورًا |
| موثوقية التنبؤ | 8–12 أسبوعًا للاتجاه، 6 أشهر لأثر الحرارة، سنة للدورة الموسمية | |

كل ذلك قابل للتعديل من متغيرات البيئة: `DARB_DAILY_FRAMES` و`DARB_CAPTURE_HOUR` و`DARB_WINDOW_START` و`DARB_WINDOW_END` و`DARB_CONFIRM_AFTER_MIN`.

## التشغيل

> **للنشر على الإنترنت:** راجع **[DEPLOY.md](DEPLOY.md)**. فيه خياران:
> - **مجاني:** التقاط يومي من كل كاميرا (5 إطارات) عبر GitHub Actions، والموقع على GitHub Pages.
> - **خادم كامل:** بأمر واحد `docker compose up -d --build`.

```bash
git clone https://github.com/ahsasgaly11-ai/darb-ai.git && cd darb-ai
python3 -m venv .venv && . .venv/bin/activate
pip install --index-url https://download.pytorch.org/whl/cpu torch torchvision   # PyTorch للمعالج
pip install -r requirements-ai.txt
python -m backend.models          # تنزيل نموذجَي RDD2022 (~40MB) إلى models/
uvicorn backend.app:app --host 0.0.0.0 --port 8000
# افتح http://localhost:8000
```

- **المناطق:** الافتراضي `DARB_REGIONS=singapore,phoenix,tucson,yuma,tampa,losangeles,sandiego,madrid`.
- **بدون الذكاء الاصطناعي:** `pip install -r requirements.txt` فقط. يعمل النظام بالرؤية الكلاسيكية تلقائيًا، وهي أقل دقة.
- **أول تشغيل:** يُبنى سجل سنغافورة (26 أسبوعًا من صور حقيقية) في الخلفية خلال 30–40 دقيقة مع الذكاء الاصطناعي. أما أريزونا فلا أرشيف لها، فيبدأ سجلها من أول التقاط نهاري ويتراكم أسبوعيًا.

أو عبر Docker (يشمل الذكاء الاصطناعي والنماذج):

```bash
docker build -t darb-ai .
docker run -p 8000:8000 -v darb-data:/data darb-ai
```

الاختبارات:

```bash
pip install -r requirements-dev.txt && python -m pytest -q tests
```

- **ميامي (FL511):** أغلبها 704×480.
- **كوينزلاند (أستراليا) وهونغ كونغ:** 320×256 تقريبًا.

## نتائج الاختبار الفعلي (أكتوبر 2026)

| الاختبار | النتيجة |
|---|---|
| **سنغافورة — 6 أشهر من صور حقيقية** (4 كاميرات، 128 لقطة) | مؤشر الحالة ثابت عند ~100 للطرق السريعة السليمة، و**صفر** تنبيهات كاذبة حرجة أو تحذيرية، و**صفر** مشكلات كاذبة. قبل هذه التحسينات كانت الحصيلة 27 تنبيهًا و14 مشكلة كاذبة. تغيّرات الإضاءة والظلال تُسجَّل ملاحظات مراجعة فقط، واستُبعدت 5 لقطات مزدحمة. |
| **شاحنة أعمال متوقفة أيامًا** (AYE، أكتوبر) | لم تُخفّض مؤشر الحالة مع الذكاء الاصطناعي. الكشف الكلاسيكي كان يخفّضه إلى 50. |
| **أريزونا — SR-87 عند Shea** | اكتُشف التشقق التمساحي الحقيقي (مؤشر حالة 31.5 = سيئ)، بينما بقيت الطرق السريعة الجيدة عند 95–100. التشققات الرفيعة في الصور الليلية فاتت النموذج. |
| **دورة الحياة (الاختبارات الآلية)** | سيناريو كامل: تنبؤ ← تحقق ← إصلاح ← مراقبة ← إغلاق، مع تتبّع العيوب ورصد الترقيع (`tests/test_darb.py`). على الطرق الحقيقية المختبرة لم تقع مشكلات خلال الأشهر الستة، فلوحة دورة الحياة فارغة حتى الآن، وهذا متوقع. |

> هذه نتائج أولية على عدد محدود من الكاميرات. الطرق الحقيقية المختبرة سليمة غالبًا، فلم نستطع قياس **نسبة الاكتشاف** (Recall) على عيوب كثيرة. قياسها يتطلب وسم عيّنة صور يدويًا.

## تفاصيل المصادر

### فينكس (AZ511)
- الكاميرات في `config/cameras.phoenix.json`: ثماني كاميرات.
  - اثنتان على **SR-87**، وفيهما تشققات حقيقية ظاهرة (منها تشقق تمساحي عند Shea)، وهما مفيدتان لاختبار الاكتشاف.
  - ست على طرق سريعة رئيسية: I-10 (ومنها نفق Deck Park)، وUS-60، وLoop 101، وSR-303.
- الصور تتجدد كل دقيقة تقريبًا، فتُجمع الدفعة على مدى بضع دقائق (`burst_interval`). صورة «No live camera feed» البديلة تُعامل كتعطّل للكاميرا.
- منطقة الطريق `roi` ضُبطت مبدئيًا من صور ليلية، وتحتاج مراجعة على صور النهار.

### لوس أنجلوس وسان دييغو (Caltrans) — فيديو متصل
- 12 كاميرا في لوس أنجلوس ومقاطعة أورانج (`config/cameras.losangeles.json`) و8 في سان دييغو (`config/cameras.sandiego.json`)، اختيرت من 217 بثًا عالي الدقة من بين نحو 1250 كاميرا.
- تبث فيديو HLS متصلًا يعرضه الموقع مباشرة (hls.js، أو مشغّل سفاري المدمج)، ويشتغل البث فقط حين تكون الكاميرا ظاهرة على الشاشة لتوفير الإنترنت.
- للتحليل تُلتقط 7 إطارات من البث نفسه ثم يُحسب الوسيط الزمني فتختفي المركبات.

### توسان ويوما (AZ511) وتامبا (FL511)
- توسان: ثماني كاميرات على I-10 وI-19 (`config/cameras.tucson.json`). يوما: كاميرتان على I-8 (`config/cameras.yuma.json`).
- تامبا: سبع كاميرات على I-275 وI-4 وطريق سلمون السريع (`config/cameras.tampa.json`)، اختيرت من بين نحو 5000 كاميرا في فلوريدا لأنها بدقة 1920×1080.
- FL511 مبنية على منصة AZ511 نفسها، فيستخدمان المحوّل نفسه (`az511` و`fl511`).
- لم تُحدد منطقة الطريق `roi` بعد، ويُستخدم الافتراضي حتى تُضبط على صور النهار.

### سنغافورة (data.gov.sg)

لم أجد حتى الآن في دول الخليج (دبي، الدوحة، الرياض، الكويت، المنامة، مسقط) جهة تنشر **صور** كاميرات المرور بواجهة مفتوحة ورخصة واضحة. في سنغافورة تنشر هيئة النقل البري (LTA) صور كاميراتها مجانًا عبر data.gov.sg، والبوابة **تحتفظ بالصور السابقة**، فيبني النظام سجلًا أسبوعيًا من صور فعلية فور التشغيل.

- لكل مجموعة مناطق قاعدة بيانات مستقلة (`data/<regions>/`).
- الكاميرات في `config/cameras.singapore.json`: أربع كاميرات بمنظر واضح للطريق (BKE وAYE وسنتوسا غيتواي ومخرج الجسر)، مع منطقة الطريق `roi` لكل منها.
- **ملاحظة:** منذ أوائل يوليو 2026 تعرض الواجهة العامة 8 كاميرات فقط بعد أن كانت 90. لذلك اختيرت الكاميرات من هذه الثماني، وهي متاحة طوال الأشهر الستة. المفتاح المجاني (`DATAGOVSG_API_KEY`) يرفع حدود الطلبات.

### ما الذي تعلّمناه من الصور الحقيقية (وعُولج)
| المشكلة في الصور الحقيقية | المعالجة |
|---|---|
| علامات الطريق والأسهم تُقرأ تشققات | استبعاد محيط العلامات البيضاء قبل البحث عن التشققات |
| الازدحام: مركبات لا يزيلها الوسيط | مؤشر «حجب» لكل التقاط؛ عند الازدحام تُجرَّب لحظات قريبة، وإلا تُستبعد اللقطة |
| مركبات متوقفة/أقماع ملوّنة | رفض المكوّنات الملوّنة (التشقق رمادي دائمًا) |
| اهتزاز أو انحراف بسيط للكاميرا | محاذاة اللقطتين (ORB + Homography) قبل المقارنة، وتنبيه عند تغيّر المنظر كليًا |
| قفزات منفردة (ظل، أرض مبتلة) | الاتجاه من اللقطات الأسبوعية بوسيط متحرك لثلاث نقاط؛ والحدث المفاجئ يحتسب فورًا متى تكرر في فحصين يوميين |
| فرق البكسلات بسبب الشمس والغيوم | مع الذكاء الاصطناعي لا يُعدّ التغيّر مشكلة إلا إذا أكّده النموذج (عيب جديد أو هبوط المؤشر)؛ وإلا يُسجَّل «تغيّر في المشهد» للمراجعة فقط |
| حفرة كاذبة من نموذج واحد (بقايا دراجة نارية) | الحفرة تتطلب اتفاق النموذجين أو ثقة ≥ 0.5، ثم التأكيد في لقطتين متتاليتين لنفس نوع الحدث |

الكشف الكلاسيكي كان **تقريبيًا** على الصور الحقيقية، لذلك أصبح الذكاء الاصطناعي هو المحرك الافتراضي. وتبقى المعالجات أعلاه (الحجب، المحاذاة، التنعيم، التأكيد على مرحلتين) طبقة حماية فوقه.

## إضافة مدينة خليجية (الدوحة مثلًا)

1. أضف مدخلًا في `REGIONS` داخل `backend/config.py` (الاسم، التوقيت `Asia/Qatar`، الإحداثيات، المتوسطات المناخية الشهرية).
2. أنشئ `config/cameras.doha.json` بكاميراتك (snapshot/MJPEG/RTSP/HLS) مع `roi` لكل كاميرا.
3. شغّل بـ `DARB_REGIONS=doha` أو أضفها مع غيرها: `DARB_REGIONS=doha,phoenix,singapore`.

مصادر الكاميرات المحتملة في الخليج تحتاج اتفاقًا رسميًا لأنها غير منشورة للعموم: هيئة الأشغال العامة «أشغال» أو وزارة الداخلية في قطر، وهيئة الطرق والمواصلات RTA في دبي، ومركز النقل المتكامل في أبوظبي. ويمكن أيضًا تركيب كاميرات خاصة أو استخدام صور مركبات الفحص.

## ربط كاميرات حقيقية

> لا تنشر جهات الخليج صور كاميرات المرور للعموم حتى الآن. عند الحصول على روابط مرخّصة (من RTA في دبي، أو «أشغال» في قطر، أو غيرهما) تُضاف مباشرة دون تغيير الكود.

الأنواع المدعومة في ملفات `config/cameras.*.json` (أو عبر `POST /api/cameras`):

```jsonc
{ "type": "snapshot", "url": "https://.../cam.jpg", "headers": {} }   // صورة JPEG تتجدد — الأشهر في كاميرات المرور
{ "type": "mjpeg",    "url": "http://.../video.mjpg" }
{ "type": "rtsp",     "url": "rtsp://user:pass@host:554/stream" }       // يتطلب OpenCV مع FFmpeg
{ "type": "hls",      "url": "https://.../live.m3u8" }
{ "type": "datagovsg", "camera_id": "4712" }                           // كاميرات سنغافورة المفتوحة (مع الأرشيف)
{ "type": "az511", "image_id": 741, "burst_interval": 20 }              // كاميرات أريزونا (ADOT)
```

يمكن لكل كاميرا تحديد:
- `meta.roi`: منطقة الطريق في الصورة كنِسَب `[[x,y],…]`، وهي مهمة لاستبعاد الأرصفة والسماء.
- `meta.aadt` و`meta.heavy_vehicle_pct`: الحمل المروري اليومي ونسبة الشاحنات.
- `meta.surface_date`: تاريخ آخر رصف.

مثال إضافة كاميرا من سطر الأوامر:

```bash
curl -X POST localhost:8000/api/cameras -H 'Content-Type: application/json' -H "X-Admin-Token: $DARB_ADMIN_TOKEN" -d '{
  "id": "dxb-cam-101", "name": "شارع الخيل — مخرج 3", "road": "D69", "lat": 25.15, "lng": 55.24,
  "source": {"type": "snapshot", "url": "https://example.org/cam101.jpg"},
  "meta": {"aadt": 70000, "heavy_vehicle_pct": 20, "surface_date": "2020-03-01",
           "roi": [[0.05,0.98],[0.95,0.98],[0.62,0.45],[0.38,0.45]]}
}'
```

## حدود النموذج الأولي وخطوات التطوير

- **أوزان نموذج المخاطر مبدئية** مبنية على أدبيات هندسة الرصف. بعد تجميع سجلات صيانة فعلية تُعايَر بالدالة `risk.fit_weights`، وتبقى مخرجاتها قابلة للتفسير بالطريقة نفسها.
- **نماذج الذكاء الاصطناعي** دُرّبت على صور من كاميرات السيارات (RDD2022)، لا من كاميرات المرور المرتفعة. التقطيع يقلّص الفجوة لكنه لا يلغيها، وفي اختباراتنا:
  - اكتشف التشقق التمساحي الواضح على SR-87.
  - لم يُعطِ إنذارات كاذبة تُذكر على الطرق السليمة.
  - فاتته تشققات رفيعة في الصور الليلية.

  الخطوة التالية **ضبط النماذج (Fine-tuning)** على بضع مئات من صور هذه الكاميرات بعد وسمها يدويًا، ثم على صور خليجية عند توفرها.
- **مؤشرات دورة الحياة** (سبق التنبؤ، زمن المعالجة) تصبح ذات معنى إحصائي بعد أشهر من التشغيل الفعلي. أما في السجل الأولي فهي توضيحية.
- **كاميرات المرور ليست مصممة لفحص الرصف**؛ النظام يرتّب أولويات الفحص الميداني ولا يحل محله. ويمكن إضافة صور مركبات الفحص أو الطائرات المسيّرة بالمحوّلات نفسها.
- **قطر والخليج**: يكفي إضافة منطقة وكاميراتها (انظر «إضافة مدينة خليجية»).
